# 配信の書き方

## 講義(kind: lesson)— 5〜10分で読める量

本文の型(見出しは内容に合わせて言い換えてよい):

1. `### 今日のテーマ` — 何を学ぶか、なぜ知っておくとよいかを2〜3文で
2. `### 仕組み` — 中心の説明。たとえ話を1つ。図の代わりに箇条書きで構造を示す
3. `### これまでの知識とのつながり` — 既存の concepts と結びつける(初回などで無ければ省略)
4. `### アプリを作るときにどう効くか` — 実際の開発や AI の使い方での注意点・活かし方。ユーザー自身のアプリ(統合ライフコーチ: スマホ向け単一HTML、IndexedDB 保存、ブラウザから Anthropic API を直接呼ぶ)に当てはめられるなら、当てはめる
5. `### 手を動かしてみる` — 実践課題の紹介(詳しい手順は practice に)

最後に `quiz` で確認2〜3問と【復習】1〜2問。

## 深掘り(kind: deepdive)— ユーザーのメモに応える

1. `### あなたのメモ` — メモの要点を引用し、良い気づきを具体的に認める(ほめるだけで終わらない)
2. 理解を広げる・正す — 誤解があればはっきり、でもやさしく直す。抜けている視点を足す
3. 体系に組み込む — カリキュラムのどこに当たるか、どの知識とつながるか
4. 実践とアプリ作りへの活かし方
5. 次につながる知識

カリキュラムに該当する回があれば `status: "done"` にする。

## ニュース(kind: news)— 3〜5本

各ニュース:

```
### 見出し(媒体名・日付)
- 何が起きたか(事実を1〜2文)
- なぜ重要か(ユーザーの学習段階の言葉で)
- つながる知識: 〇〇(既存の concept があれば名前を出す)
```

最後に `### 今日のひとこと` で、ニュース全体から見える流れを2〜3文。`sources` に全記事の URL を入れる。ニュースの中で新しく出てきた重要な用語は concepts に登録してよい(1回に1〜2個まで。増やしすぎると復習が回らない)。

## 実践課題の作り方

- 20〜30分で終わる大きさ。手順は具体的なコマンドや操作で書く
- 安全に試せる場所を指定する: Claude Code のクラウド環境(使い捨ての箱)、ブラウザの開発者ツール、テスト用のフォルダなど。ユーザーの本番データ(統合ライフコーチの記録)を壊す可能性のある手順は書かない
- 「やってみて何が分かったかをメモに書く」を最後の手順にすると、深掘りのループが回る
- 前の課題が `done` なら、その発展課題を優先する

## 会話への返答

定期実行の配信では、記録を書いたあと、会話に次の内容を短く返す(スマホの通知で読まれる前提)。

- タイトルと要点3行
- 今日の復習問題1問(答えは書かない。ページで見られる)
- 学習帳のリンク: https://claude.ai/artifact/1hcwDxrA9z3uko6KKR1xgu
