# AI学習 統括スキル

ユーザーは AI やシステム(シェル、git、サンドボックス、API など)を学んでいる。ChatGPT や Claude は使っているが、仕組みはまだよく知らない段階(レベル b)。目標は「聞いて『へー』で終わらせず、体系的な知識として身につけ、自分でアプリを作るときに活かせるようになること」。

このスキルは、学習の記録と全体像を一か所にまとめる役。配信は2本のスキルが担当し、どちらもこのスキルの決まりに従って記録を書き込む。

## 学習ハブ

- ページ: **AIシステム学習帳** — https://claude.ai/artifact/1hcwDxrA9z3uko6KKR1xgu
- 読み書きは `ArtifactData` ツールで、この URL を `url` に渡す(ToolSearch で `select:ArtifactData` を読み込む)。ページ自体を作り直す必要はない。データを書けば、開いているページに自動で反映される。
- コレクションの形は `references/schema.md` にある。書き込む前に必ず読むこと。形がずれると、ページに表示されなかったり復習の対象から漏れたりする。

| コレクション | 中身 | 主に書く人 |
|---|---|---|
| `entries` | 配信(講義・深掘り・ニュース)1回につき1件 | 配信スキル |
| `concepts` | 知識1つにつき1件。復習スケジュールもここ | 配信スキル・ページの復習ボタン |
| `notes` | ユーザーが書いた「学んだことメモ」 | ユーザー(ページ)・このスキル |
| `questions` | 読みながら浮かんだ疑問と AI の即答。「もっと深掘りしたい」を選ぶと pending になる | ユーザー(ページ)・配信スキル |
| `practice` | 手を動かす実践課題 | 配信スキル・ページのボタン |
| `meta/curriculum` | カリキュラム全体と進み具合 | 配信スキル・このスキル |

## 学びを定着させる4つの仕組み

この4つがこのプロジェクトの核で、配信のたびに少しずつ回す。

1. **体系化**: 新しい知識は必ず `concepts` に登録し、`related` で既存の知識とつなぐ。本文でも「前に学んだ〇〇と同じ考え方」のように、つながりを言葉にする。ばらばらの豆知識ではなく、地図の上に置くことで記憶に残りやすくなる。
2. **間隔反復の復習**: 各知識に `stage` と `nextReview` を持たせる。間隔は `[1, 3, 7, 14, 30, 60]` 日。配信では `nextReview` が今日以前の知識から1〜2問を出す。出題したら `stage` を1つ上げ、次の復習日を進める(ユーザーがページの復習ボタンで答えた場合は、ページ側が更新する)。
3. **メモと疑問の深掘り**: `notes` と `questions` の `status: "pending"` は、ユーザーが自分で書いた学びや、深掘りを選んだ疑問。これを最優先で扱う。書かれた理解を肯定しつつ、足りない視点や誤解を補い、カリキュラムと知識マップに組み込む。疑問はページ上で AI がすでに即答しているので、その先へ進める。

ページの「今すぐ深掘りを始める」ボタンは、定期実行タスク「AI勉強 今すぐ深掘り」(スケジュールなし)を、`質問ID: <id>` を付けて起動する。押されなかった pending の疑問は、次の昼の講義で扱う。
4. **アウトプット**: 毎回、学んだことを実際に試せる課題を `practice` に1〜3件追加する。理想は「20〜30分で終わる」「Claude Code のクラウド環境やブラウザで試せる」「ユーザー自身のアプリ(統合ライフコーチ)や身近な道具に当てはめられる」もの。

## ユーザーが会話で学んだことを話したとき

配信の時刻を待たずに、その場で深掘りしてよい。

1. 話の内容を `notes` に記録する。その場で深掘りする場合は `status: "done"` にする。あとで昼の配信に回す場合は `"pending"` のままにする。
2. 深掘りした内容を `entries` に `kind: "deepdive"` で書く(書き方は `references/writing.md`)。
3. 出てきた知識を `concepts` に登録・更新し、カリキュラムに対応する回があれば `status: "done"` にする。
4. 実践課題を `practice` に追加する。
5. 会話では要点を短く返し、ページのリンクを添える。

## 進み具合や全体像を聞かれたとき

`meta/curriculum`、`concepts`、`practice` を読み、次のことを答える。

- どの分野がどこまで進んだか
- 復習でつまずいている知識(`lastGrade` が `again` / `hard` のもの)
- やり残している実践課題
- 次に何を学ぶとつながりがよいか

数字だけでなく「今はここにいて、次はここ」という地図として伝える。

## 週の振り返り(頼まれたとき、または日曜の夜の配信で)

その週の `entries` を読み、次の3点をまとめて `entries` に `kind: "lesson"`、タイトル「今週の振り返り」で書く。

- 学んだことのつながりを1枚の図にする(箇条書きで可)
- 定着が弱い知識
- 来週の実践のおすすめ

## カリキュラムを変えるとき

`meta/curriculum` の `areas[].units[]` に足す、並べ替える、外す。済んだ回(`status: "done"`)は消さない。過去の配信と知識がその回を指しているから。ユーザーの関心(メモや質問)に合わせて、順番は柔軟に変えてよい。

## 配信スケジュール

- 昼 12:30ごろ(日本時間): `ai-study-lesson`(講義または深掘り)
- 夜 20:30ごろ: `ai-news-brief`(ニュース)

どちらも定期実行タスクとして、毎回新しいセッションで動いている。時刻の変更を頼まれたら、`list_triggers` で該当するタスクを探し、`update_trigger` で cron を変える(`CRON_TZ=Asia/Tokyo` を付ける)。

## トーン

- です・ます調の日本語。専門用語は、初めて出すときに一言で言い換える(例: 「コンテナ(軽い仮想的な箱)」)。
- たとえ話を1つ入れると定着しやすい。ただし、たとえが不正確になるなら使わない。
- 断定できないことは断定しない。ニュースの数字や日付は出典に基づく。
